# Import format (CSV)

Hanzi SRS imports vocabulary from a **UTF-8 CSV file**. You choose the target deck in the app
(an existing deck, or a new one) — the deck is not part of the file.

Download a template from the import screen, or from the repository:

- [`hanzi-srs-template.csv`](../public/templates/hanzi-srs-template.csv) — comma-separated
- [`hanzi-srs-template-semicolon.csv`](../public/templates/hanzi-srs-template-semicolon.csv) —
  semicolon-separated (what Excel expects with Spanish and most European regional settings)

## Columns

The first row is the header. Column names are matched ignoring case and surrounding spaces;
order does not matter. No other names are accepted.

| Column    | Required | Content                                                                       |
| --------- | -------- | ----------------------------------------------------------------------------- |
| `hanzi`   | yes      | The word in Chinese characters, e.g. `你好`.                                  |
| `pinyin`  | no       | Tone marks (`nǐ hǎo`) or numbers (`ni3 hao3`). Empty → generated (see below). |
| `meaning` | no       | Any text. Empty → stays empty and editable (dictionary lookup arrives later). |
| `tags`    | no       | Several tags separated by `\|`, e.g. `hsk1\|greeting`.                        |

```csv
hanzi,pinyin,meaning,tags
你好,nǐ hǎo,hello,greeting|hsk1
谢谢,xièxie,thank you,
朋友,,friend,people
```

Tags use `|` and not `;` because `;` is also a column separator.

## Separators, quotes and line breaks

- The separator is detected from the header: comma `,`, semicolon `;` or tab.
- A cell containing the separator, a quote or a line break must be wrapped in double quotes;
  a quote inside a quoted cell is written twice: `"say ""hi"""`. Excel does this automatically.
- Windows (CRLF) and Unix (LF) line endings both work. Blank lines are ignored.
- A UTF-8 byte order mark (BOM), which Excel adds, is accepted.

## Encoding: UTF-8 only

The file must be UTF-8. If it is not (for example a "CSV (Comma delimited)" file saved by Excel
in a legacy encoding, or GBK/GB18030), **nothing is imported** and the app asks you to save it
again as CSV UTF-8. Characters are never guessed or replaced.

### Saving from Excel

1. **File › Save As** (on Mac: **File › Save As…**; in Spanish: **Archivo › Guardar como**).
2. In **Save as type** / **Tipo**, choose **CSV UTF-8 (Comma delimited) (\*.csv)** —
   in Spanish **CSV UTF-8 (delimitado por comas)**. Do _not_ pick the plain "CSV (Comma delimited)".
3. Save. With Spanish regional settings Excel writes `;` instead of `,` even though the name says
   "comma" — that is fine, the separator is detected.

From Numbers (Mac/iPhone): **Share › Export › CSV**, text encoding **Unicode (UTF-8)**.
From Google Sheets: **File › Download › Comma-separated values (.csv)** (always UTF-8).

On iPhone, keep the file in the Files app (iCloud Drive or On My iPhone) and pick it from the
import screen of the app _installed on the Home Screen_ (its storage is separate from Safari's).

## Limits

- Up to **2 MB** and **5000 rows** per file. Split bigger lists into several files.

## What the preview shows

Nothing is saved until you confirm. Every row gets a status, written as text and a symbol:

| Status      | Meaning                                                                                           | Imported?                                   |
| ----------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| + New       | Not in the deck yet.                                                                              | yes                                         |
| ↺ Restore   | You deleted this word from the deck before; it comes back with its history.                       | yes                                         |
| = Duplicate | Same hanzi earlier in the file (the first row wins), or already in the deck with the same data.   | no                                          |
| ≠ Changed   | Already in the deck, but the file has a different pinyin, meaning or tags.                        | only if you tick "Update the changed words" |
| ✕ Error     | Empty hanzi, no Chinese characters, or cells beyond the header (usually a separator/quote issue). | no                                          |
| ⚠ Warning   | Shown in addition to the status. The row is still imported exactly as written.                    | yes                                         |

Only columns that are filled in the file can update a saved word: an empty cell never erases
anything, and generated pinyin never replaces saved pinyin.

### Pinyin check

The app compares your pinyin with the pinyin generated by [pinyin-pro], ignoring capitals,
spaces and the notation (`nǐ hǎo` = `Ni3Hao3`), and warns when they differ:

- **differs** — another word's pinyin, a missing syllable, or a wrong tone;
- **no tone marks** — e.g. `ni hao`.

Both forms of the tone changes of 不 and 一 are accepted (`bú shì` / `bù shì`, `yí gè` / `yī gè`).
A syllable without tone is accepted only where the reference reading is neutral: `māma` for 妈妈,
`xièxie` for 谢谢 (a repeated character), but `xuéxi` for 学习 gets a warning. Some common
neutral-tone words (朋友 `péngyou`, 先生 `xiānsheng`) still get a warning for now — check them and
keep your pinyin. A better reference arrives with the dictionary (CC-CEDICT marks neutral tones).

Your pinyin is **never overwritten silently**. Tap **Use suggestion** on a row to take the
generated pinyin for that row. If the `pinyin` cell is empty, the generated pinyin is used and the
row is marked **generated**.

Importing the same file twice does not create duplicates.

[pinyin-pro]: https://github.com/zh-lx/pinyin-pro
